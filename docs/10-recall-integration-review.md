日期：2026-09-06。补丁基线：`e7c6b9d1c93811d5bb0b735e223658a4d205d360`；历史基准实验对应其前驱 `433b1256`。

## 一、实际修改

| 范围 | 修复与边界 |
| --- | --- |
| 向量数值 | 先按最大绝对值缩放再归一化，避免有限的大数平方溢出与极小值平方下溢；错误向量明确失败。 |
| 向量发布 | 编码前读取来源版本，编码后在写事务中重新检查；来源改变时拒绝写入过期向量。编码按 64 条分批，不在编码期间持有数据库写事务。 |
| 存储入口 | 拒绝把其他 SQLite 数据库当作召回索引或观察输出；provider 使用只读连接，缺失数据库不自动创建。 |
| 并发与缓存 | 同一实例的写入、检索和关闭串行化；外部数据库更新通过 data_version 清除缓存。本机同权限进程恶意修改不在隔离保证范围。 |
| 检索速度 | 候选正文批量读取；原生 UTF-8 字节计数采用增量预算计算；最多缓存 64 份明确输入的查询结果，返回独立副本。不同查询、预算、模型及索引变化不能误用旧结果。 |
| 预算与输入 | 拒绝布尔类型伪装的候选数和邻轮数；计量器必须返回非负整数，非空文本必须有正成本；最终预算再次核对。零预算不会调用语义编码器。 |
| scan | 扫描后续出现的锚点，寻找 200 字符范围内的不同条件组合；处理未闭合反引号/波浪线代码围栏；大小写等价别名不能充当两个独立条件。 |
| scan 范围 | 锚点先验证；消息时间规范化为 UTC；来源类型大小写统一；记录数、文本字节、时间和每个锚点的出现数有上限，达到上限报告 partial。 |
| 数据读取 | 在 SQL LIMIT 前排除后台/测试等消息，避免它们占满正常会话的读取限额。使用只读事务核对 schema 和 profile，不加载宿主的迁移代码。 |
| 衰减输入 | 检查事件、日期、重复身份、确认依据、固定状态及参数类型；不让错误元数据改变驻留评分。曲线默认值没有自动应用到真实用户数据。 |
| 评测 | 修正 LoCoMo 类别标签，独立每段对话的 FTS 统计；新增 p99、MRR 和 nDCG。数据文件哈希不符时不宣称属于已固定的上游版本。 |

`scan` 仍只产生 `mention_observed`，权重为零；没有生成使用证据、延长有效期或自动换层。检索候选、最终装载的证据和回答正确性仍分开。

## 三、评测协议为何需要修正

### 类别标签

LoCoMo 的类别 1 为 multi-hop、类别 4 为 single-hop。原脚本将两个名称互换。原 1–4 总计不因名称互换而改变，但类别解释要纠正。依据为上游固定提交的 `task_eval/evaluation.py`，其中类别 1 使用多答案分项评分。

### 不同对话的 IDF 统计

FTS5 的 BM25 统计来自整张 FTS 表。原脚本不断向同一个数据库添加对话，即使使用 scope 过滤返回内容，先前对话也会改变后续对话的 IDF。内容没有跨 scope 返回，但评分会依赖数据集遍历顺序。

协议 2 每段对话使用独立数据库，避免这项交叉影响，并明确报告 `idf_scope`。生产环境的多 scope 共享库仍使用全库统计；本补丁没有宣称已经提供统计隔离的生产索引。如果业务需要完全独立排名，应分别建立索引。

### 新增指标与时间口径

新增 MRR、nDCG、p99。MRR/nDCG 使用按预算实际装载的证据顺序；邻轮展开后的顺序属于上下文顺序，不应被当成纯模型重排质量。没有保存顺序的历史 artifact 不能追补这些指标。

重复查询命中完整结果缓存时，单独报告 `result_cache_hit`。该延迟不与未缓存查询混为一谈；cold start、模型加载、来源导入、模型生成及用户感知时延仍需单独测量。

## 四、本补丁的实际本地验证

[测试日志](../reports/2026-09-06-recall-review-tests.txt)中 95 项通过：48 项精确取自基线的扩展/评测/数据库保护测试，47 项本轮新增回归。新的前 28 项回归在先前未修复的 `433b1256` 基线上得到 24 个失败、3 个错误、1 个通过；[原始失败日志](../reports/2026-09-06-recall-review-before.txt)保留。

本地只取得了相关源码与测试的精确字节。原索引核心的 87 项测试没有在这份部分工作树里重新运行，其源码未被本补丁改动；基线的远端 correctness CI `34030697736` 已通过。发布前必须在完整仓库重新运行所有测试，不能把两处结果相加成虚构的联合通过数。此前替代 ZIP 的 87 项测试也单独复跑通过，但没有将那套实现混入当前包。

额外微基准使用 500 条合成资料、80 个不同查询及 200 次相同查询。基线与补丁的 80 份上下文和排名完全一致。在本次 Linux/Python 3.13.5 进程中：

| 未缓存的不同查询 | 3.507 ms | 2.754 ms |

## 五、兼容与剩余验证

调用入口 `python -m thm` 和既有索引 CLI 保留。`SearchIndex(..., readonly=True)` 是新增可选参数；表格式未迁移。重复 session/order、非法参数、不是召回库的路径现在会明确拒绝。扫描结果版本为 2；旧观察不被改成新的有用性事件。动态 provider 使用只读连接，没有开启后台写入。

本次补丁未运行修正协议 2 的完整 LoCoMo，没有下载真实语义模型，没有实际连接安装中的 Hermes，也没有迁移用户配置、索引、记忆或定时任务。当前机器上的同步通道只读，补丁已本地验证但尚未推送远端。它不能被描述为已发布的 1.2.1 或已经改善本机端到端效果。

补丁应用到完整仓库后的验收命令：

```bash
python -m unittest discover -s tests -v
python scripts/thm_numeric_audit.py
python scripts/check_docs.py
```

随后用 workflow_dispatch 显式运行原 benchmark 工作流的协议 2 并保留新 artifact；本轮保留了远端的重型实验按需触发规则。旧协议结果保持不变，以便核对。
