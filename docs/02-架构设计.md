# 分层热交换记忆体系（THM）—— 架构设计

版本 v1.0 · 2026-08-18 · 依据：《01-研究综述.md》十条设计公理

---

## 〇、目标函数（第一性原理表述）

记忆系统要最大化的不是"记住多少"，而是：

    E[任务成功率] = P(正确的事实在正确的时刻出现在上下文里)
                    − λ1 · 注入成本(token/轮)
                    − λ2 · 注意力稀释(热层越大,单条可见度越低)
                    − λ3 · 干扰税(重复/矛盾条目共存)

所有设计决策都是这个函数下的权衡。推论：**"在某层存着"不等于"在上下文里"**——提取链路（索引→检索→注入）与存储本身同等重要。

λ 标定进展（2026-08-19）：λ1 注入成本已由 context-economics 研究 L4-memory-profile.md 完成实测标定
（T0 驻留租金 default ≈2,322 tok/轮、命中下 $0.0007/轮——量级结论：装满不是经济问题；
真正的成本事件是中途写入断缓存前缀，守则=批量/早末写）。λ2/λ3 待巩固 cron 积累 events 后标定。

## 一、四级存储层级

```
层级      生物对应        计算对应      载体(Hermes 落地)                访问方式
─────────────────────────────────────────────────────────────────────────────────
T0 热层   工作记忆        L1 缓存       MEMORY.md + USER.md             每轮自动注入
                                        (容量 3750/2350 字符,与 Hermes 运行时注入预算一致)
T1 温层   语义长时记忆    L2 缓存       memory-system/warm/*.md         agent 按主题
                                        (按主题分文件,无硬上限)          主动 read_file
T2 冷层   情景长时记忆    主存/磁盘     会话 state.db(session_search)    按关键词检索
                                        + memory-system/archive/*.md
T3 冰层   外部世界        远端存储      配置文件、论文 PDF、官方文档、    回到源头现查
                                        Clash yaml、注册表……            (记忆只存指针)
```

与 CPU 缓存的关键差异（必须正视，否则类比误导）：
1. CPU 缓存对 CPU 透明；本系统的 T1/T2 **对模型不透明**——模型必须"知道那里有什么"才会去取。因此**索引（manifest）是本系统最重要的单一组件**：没有索引的冷存储等于不存在。
2. CPU 换页由硬件在纳秒级完成；本系统换页发生在"轮"的尺度，因此换页策略必须是**预判式**（在写入/巩固时决定层级），而不是缺页时被动换入。
3. T3 的存在是认知科学里没有的层次：很多"记忆"根本不该内化，只该存指针（"Clash 直连规则写在哪个 yaml 的哪一段"），需要时回源头读。这避免了记忆与世界状态脱节（stale memory 是幻觉温床）。

## 二、元数据：每个条目一张"缓存行标签"

`index.json` 为 T0/T1 每个条目维护：

```json
{
  "id": "m-gw-parent-child",
  "tier": "T0",
  "store": "MEMORY.md",
  "key": "gateway 父子进程",            // 用于在 MEMORY.md 中定位条目的唯一子串
  "summary": "VBS 起 launcher→spawn uv worker,勿当重复误杀",
  "created": "2026-08-17",
  "events": [                            // ACT-R 激活的事件流
    {"t": "2026-08-17", "type": "create"},
    {"t": "2026-08-18", "type": "hit", "note": "排查 gateway 时用到了"}
  ],
  "cost_class": "high",                  // 缺失代价: high(事故级)/med/low
  "next_review": "2026-08-24"            // 间隔重校验到期日
}
```

事件类型：`create`（写入）、`hit`（被提取并派上用场）、`confirm`（重校验确认）、`demote/promote`（换层）。

## 三、换页策略（热交换的核心）

### 3.1 激活分数（ACT-R base-level，公理 2）

    A(i) = Σ_j  (days_since(event_j) + 1)^(−d)     d = 0.5
    事件权重: hit ×2.0, confirm ×1.5, create ×1.0

与 ACT-R 标准式 B = ln(Σ_j t_j^(−d)) 的形式差异说明（2026-09-06 复审补）：本实现省略 ln（单调变换，不改变条目排序）并加 +1 平滑（避免 t=0 除零）。阈值 0.6/0.3 按此无 ln 形式标定，与综述第三节引用的标准式不可直接对号入座。

### 3.2 晋升（promote，冷→热）

- T1→T0：90 天内 hit ≥3 次 且 cost_class=high，或用户显式纠正"这个你应该记住"。
- T2→T1：同一主题在 3 个以上不同会话被 session_search 命中 → 巩固进程将其提炼为温层条目。

### 3.3 驱逐（demote，热→冷）

- T0→T1：激活 A < 阈值（默认 0.6）且 age > 21 天 且 cost_class ≠ high。
- T1→T2：激活 A < 0.3 且 90 天无 hit。
- 驱逐不是删除：内容完整保留在下一层，只失去"自动注入"特权。

### 3.4 写入闸门（admission，公理 6/8）

新事实写入前过三问：
1. **稳定性**：7 天后还成立吗？（任务进度、一次性状态 → 拒收，属会话内容）
2. **提取频率**：预期多久用一次？（每次都需 → T0 候选；按主题 → T1；罕见 → T2/指针）
3. **缺失代价**：忘了会出事故吗？（事故级 → cost_class=high，享受驱逐豁免）
另有两道加工检查：必须是提炼后的陈述句（拒收转录/原文）；与现有条目查重/查矛盾（近似即合并，矛盾即裁决，不共存）。

### 3.5 巩固进程（consolidation，公理 3/4，"睡眠"）

周期 cron（每周）做四件事：
1. 扫描近 7 天会话：反复出现的未记忆模式 → 提议晋升；
2. 重算全部 T0/T1 条目激活 → 输出降级提议清单；
3. 模糊查重 → 输出合并提议；
4. 间隔重校验到期清单（见 3.6）。
产出报告存 `memory-system/reports/`，由 agent（或用户）执行裁决。**弱化与强化同做，才叫巩固。**

### 3.6 间隔重校验（spaced revalidation，公理 7）

条目创建/确认后排期：+3 天 → +7 天 → +30 天 → +90 天（确认一次推进一档）。
到期未确认且激活低于阈值 → 自动进入降级提议。这解决了"记忆写入时正确、半年后悄悄过期"的腐烂问题（stale memory）。

### 3.7 排序（公理 9）

MEMORY.md 内条目按激活降序排列（最高激活在文件首）。USER.md 同理。每次巩固进程顺带给出排序建议。

## 四、与 Hermes 原生机制的边界（不重新造轮子）

- **T0 的写入通道仍是 Hermes memory 工具**（它有注入扫描、原子批量、字符预算检查）。本系统不直接改 MEMORY.md，只产出"提议"，由 agent 用 memory 工具执行。
- **T2 的检索通道仍是 session_search**（FTS5 已建好，不重造）。
- **触发域知识仍走 skills**（公理 10：skill 就是前瞻记忆机制，不该搬进 MEMORY.md）。
- 本系统新增的只有三样：**index.json（缓存行标签）、warm/（T1 载体）、thm.py（换页策略引擎）**，外加一个 skill 让未来的自己会使用这套系统。

## 五、隐私与安全

- 温层文件在本机，与 MEMORY.md 同级暴露面，不扩大泄露半径。
- index.json 不含条目全文（只含 key/summary），即使泄露也不直接暴露记忆内容。
- 全家隔离：本系统只覆盖 default profile；dad/mom 若需要，各自独立部署、各自 index，绝不共享 hits/事件流（事件流即行为画像）。
