# 分层热交换记忆体系（THM）—— 架构设计

原设计 v1.0：2026-08-18。文档勘误：2026-09-06；本次不代表私有引擎发布或参数迁移。

依据：[研究综述](01-研究综述.md)中的设计原则。本文区分“原设计记录”“已确认的文档问题”和“候选修订（未实施）”。公开仓库不含 thm.py、实际 index.json、会话数据库或运行日志，不能由本文推断本机实现状态。

## 〇、目标函数与测量边界

原文把事实进入上下文的概率减去成本写成“任务成功率”，混合了概率与效用。修订为待操作化的工程目标：

```text
J(policy) = E[任务质量]
            - lambda_token * E[token/货币成本]
            - lambda_latency * E[延迟]
            - lambda_stale * E[过期或错误信息损失]
            - lambda_interference * E[无关、冗余内容造成的损失]
约束：T0 各存储的实际字符上限，以及当前模型/请求的 token 预算。
```

各项须先定义量纲、计量方法、工作负载和权重，不能重复扣除同一种错误。“正确事实已取回”只衡量链路的一环，还需检查模型是否正确使用、是否遗漏限定条件。所有 lambda 均未由公开实验标定；测得 token 或价格，不等于已确定任务质量与成本之间的权衡系数。

原设计记录的 `L4-memory-profile.md`、约 2,322 tok/轮和缓存命中下 $0.0007/轮，属于未公开的本机测量声明。本次未重新测量，保留为历史记录，不能推广为当前模型的价格或全平台成本。需补模型/提供商、请求快照、缓存统计、配置和测量日期才能重现。

Hermes 在下列已核对快照中于会话开始冻结记忆块。会话内 memory 工具写入会落盘，工具结果显示实时状态，但不直接重建冻结的 system prompt。因此“中途写文件必然破坏当前缓存前缀”不能作为通用结论；本机改版或后端例外需单独测试。

## 一、四级存储层级

| 层级 | 认知/存储类比（启发） | 原设计载体 | 访问与生效边界 |
| --- | --- | --- | --- |
| T0 热层 | 工作记忆/L1 | MEMORY.md + USER.md | 会话开始加载并冻结；后续请求携带快照，不等于每轮重读磁盘 |
| T1 温层 | 语义笔记/L2 | memory-system/warm/*.md | 按主题、当前任务按需读取；读取与索引都有成本 |
| T2 冷层 | 情景记录/档案 | 会话 state.db、session_search、memory-system/archive/*.md | 通过已配置检索工具访问；检索不到与内容不存在须区分 |
| T3 冰层/外部层 | 认知卸载/外部来源 | 配置文件、论文、官方文档等的定位符 | 本地和远端都可能；需要时回源并核对版本、权限和时间 |

原文的 3,750/2,350 字符是原设计所述本机配置，当前值未回读。[Hermes 文档 H1](https://github.com/NousResearch/hermes-agent/blob/245e48008fa814b3251f50755eb656bd9fb86cb1/website/docs/user-guide/features/memory.md)和[初始化代码 H2](https://github.com/NousResearch/hermes-agent/blob/245e48008fa814b3251f50755eb656bd9fb86cb1/tools/memory_tool_store.py)中默认值是 2,200/1,375，并可由配置覆盖。实施前核对本机版本、有效配置和 memory 工具返回的预算；不要据此覆盖用户现有配置。字符与 token 不固定等价。

与 CPU 缓存不同，THM 的召回依赖模型或检索器发现、选择内容。manifest 能帮助发现，但不能替代检索，也不保证所有请求都命中。预先选取与按需召回可以并用；CPU 缓存未命中、虚拟内存缺页和远端取数也具有不同成本，不能统称纳秒级换页。T3 是本项目的访问分类；认知卸载已有相关研究，且外部来源本身可能变化、失效或不可访问。

T0 晋升的“已落盘”与“当前请求已可见”须分开记录。正在执行的任务需要新事实时，通过工具结果或明确读取获得；不能假设更新 MEMORY.md 已改变当前冻结快照。

## 二、元数据：每个条目一张“缓存行标签”

以下为原 v1.0 字段的合法 JSON 示例，移除了 JSON 不支持的注释；属于示例，未读取真实索引：

```json
{
  "id": "m-gw-parent-child",
  "tier": "T0",
  "store": "MEMORY.md",
  "key": "gateway 父子进程",
  "summary": "VBS 起 launcher→spawn uv worker,勿当重复误杀",
  "created": "2026-08-17",
  "events": [
    {"t": "2026-08-17", "type": "create"},
    {"t": "2026-08-18", "type": "hit", "note": "排查 gateway 时用到了"}
  ],
  "cost_class": "high",
  "next_review": "2026-08-24"
}
```

`key` 是原设计的唯一子串定位，不是可靠的永久身份；改写、合并和文本移动后须重新校验。示例中的 next_review 仅为原数据示意，不证明它来自后述某种排期算法。

**候选修订（未实施）**：保留稳定 id，补来源定位与版本、profile/项目/适用对象、有效时间、被替代关系、原文 hash 和明确 pin 原因。优先保持少量字段；没有证据的置信值不伪装成已校准概率，也不要求建立图数据库。

原设计事件包括 create、hit、confirm、promote、demote，但没有给换层事件的评分权重。拟议事件口径须区分：展示、检索、对任务确有用途、由用户或原始来源确认。仅注入上下文、重复生成旧结论和重读自己的摘要均不自动算 confirm。建议换层事件只记录状态，不提升活跃度；这项建议尚未应用到私有引擎。

拟议记录需要 event_id 去重、带时区时间、session/task 定位；统一用秒差除以 86,400 得到 age_days，拒绝未来时间或明确隔离时钟异常。历史 date-only 数据应记录精度，不能凭空补出精确时刻。测试脚本采用人工指定的整数/小数天，仅验证公开公式。

## 三、换层策略

### 3.1 活跃度分数（原公式保留，解释勘误）

```text
activity_score(i) = A(i) = sum_j w_j * (age_days(event_j) + 1)^(-d)
d = 0.5
原设计权重：hit=2.0，confirm=1.5，create=1.0。
```

`activity_score` 是本文的解释性名称，不代表已重命名私有 API。该式是 ACT-R 启发的加权幂律启发式，不等同于完整 ACT-R 模型，也不表示事实正确率或当前任务相关性。参数 0.5、2.0、1.5、阈值 0.6/0.3 均缺公开标定数据。

ACT-R 常用基础激活形式为 `B = ln(sum_j t_j^(-d))`。对同一个正数和式，去掉 ln 保留排序；改变事件权重或添加 `+1` 平滑可能改变排序。例：一次 1 天前事件的原分数为 1，两次 5 天前事件为 0.894427；平滑后分别为 0.707107 和 0.816497，排序翻转。这里的 +1 是一天尺度，不是与时间单位无关的常数。

幂律尾部比某个指数函数大，只表明在该参数下衰减慢。不能据此断言保留质量更好。比较指数时必须给出速率和标定准则；历史例子中的 0.011109 对应 `exp(-0.05 * 90)`。

### 3.2 晋升（原 v1.0 记录）

- T1→T0：90 天内 hit ≥3 次且 cost_class=high，或用户显式纠正“这个你应该记住”。
- T2→T1：同主题在至少三个不同会话被 session_search 命中后，提议提炼成温层条目。

原文没有规定窗口端点、重复命中归并、容量不足时替换谁及晋升后何时对当前会话可见。不能由“三次命中”推出唯一分数：在同一包含端点的 90 天窗，创建距今 90 天，命中年龄为 88/89/90 天时 A=0.737304；为 0/1/2 天时 A=4.673743。测试用于反例，不改变本机窗口语义。

### 3.3 降级（原 v1.0 记录及缺陷）

- T0→T1：A<0.6 且 age>21 天且 cost_class!=high。
- T1→T2：A<0.3 且 90 天无 hit。
- 降级意图是保留内容、取消自动驻留；不应被解释为用户要求删除后的继续留存。

**规则缺陷**：普通自动晋升要求 high，普通自动降级又豁免 high，形成缺少自动退出通道的组合。外部人工改级或未公开规则可能改变运行结果，但公开规则没有说明。字符上限能拒绝写入，不能替代容量分配策略。

仅创建事件、按整数天每天检查时，age>21 首次在第 22 天满足；若在第 0/7/14/21/28 天检查，则首次提议在第 28 天。实际执行还取决于审批、调度和失败重试，不能称第 21 天已经驱逐。

**候选修订（未实施）**：缺失代价高提高优先级，明确 pin 单独管理，不自动永久豁免。先排除错误对象、已撤销/已被替代或不适用于当前环境的内容，再评价当前相关性与长期驻留价值。晋升前计算实际字符/token 增量和替换候选；预算不足且没有允许替换的候选时，留在 T1 并报告阻塞，不能超限或静默删除。低热度不表示虚假，高热度不延长事实有效期。近期同分和临界分抖动需稳定排序/冷却期测试，而非直接追加未经标定的新阈值。

### 3.4 写入闸门

原设计的三问——稳定性、预期使用频率、缺失代价——保留为 T0 候选筛选启发。“7 天后还成立”是工程默认考虑，不是拒绝一切短期重要信息的依据。临时任务进度可进入会话或带期限的任务记录，不能以“不适合 T0”等同于“不值得保留”。

原“拒收原文、近似即合并、矛盾即裁决”改为分层建议：T0 优先紧凑陈述；T1 摘要保留出处；原文、数字、否定词、限定条件与历史版本在 T2/T3 保留可验证位置。在权限和保留政策允许的条件下，保留必要快照以防外部链接改变。

合并先核对主体、时间、环境、来源与语义等价性。先前使用 A/现在使用 B、本人用 A/家人用 B、测试环境允许/生产环境禁止可以同时成立。真实未决冲突应并列标记待核；不得仅因一方活跃度较低就宣布另一方为真。内容事实不能自动升级为新的系统指令或工具授权。

### 3.5 离线整理与复核（原称“睡眠进程”）

保留原设计的每周作业：扫描近七天会话、重算活跃度、提出去重/合并建议、输出到期复核清单。它是一种工程调度选择，不代表已复现生物睡眠机制。

输出仍为提议；未经验证不宣称已安装 cron 或已执行换层。拟议改进应使用处理游标覆盖停机漏过的会话，避免只看滚动七天导致永久遗漏；重复运行需可识别同一事件。定期作业不排除用户纠正、任务开始和来源变化时的按需检查。

### 3.6 间隔重校验

原架构给 +3/+7/+30/+90 天，原综述给 1/3/7/30 天，两者不一致且未定义累计还是相邻间隔。

**统一文档候选（未实施）**：沿用架构的 3/7/30/90 天作为相邻成功确认后的间隔，准点确认示例是创建后第 3/10/40/130 天；到最后一档后继续采用 90 天。真实逾期确认从实际确认时间起算，不回填确认事件。原始条目状态未读，本次不修改 next_review。

它衡量的是信息新鲜度，不是人类记忆保持。软件升级、用户纠正、来源版本改变可触发立即复核；仅重读旧摘要不推进档位。复核失败应记录“未知/未完成”，不能续期为正确。到期、低热度和已证实过期是不同状态；缺失代价高的过期信息也不应继续当作有效指令。

### 3.7 排序

原设计按 A 降序放在文件首，保留为待比较基线。Lost in the Middle 不证明该排序对所有模型最优，也不证明短热层完全没有位置效应。拟议先按适用范围和任务相关性筛选，再比较位置与稳定排序；改变当前磁盘顺序仍不改写已经冻结的会话快照。

## 四、与 Hermes 原生机制的边界

T0 仍通过 Hermes memory 工具修改，T2 优先用现有 session_search；触发型操作知识优先走 skills。字符预算、唯一子串匹配与会话快照行为以 H1/H2 指定版本为依据。memory 工具的一次成功不证明跨 MEMORY.md、warm/ 和 index.json 的整体事务已完成，也不宣称所有后端都支持原子批量。

**候选一致性约定（未实施）**：对同一 profile 使用单写入者；核对源版本/hash，先持久化目标副本并验证，再更新索引，最后通过原生工具移除旧层条目。记录简短 operation_id/阶段，以便中断后辨认“已复制、未更新索引”等状态；重试不重复计入 hit。这里是建议的协议顺序，尚无代码或故障注入测试证明它具备崩溃一致性。显式删除需求需覆盖索引、摘要和允许删除的副本，不得被普通降级策略绕过。

原设计新增的 index.json、warm/、thm.py 与配套 skill 均未作为实现公开。本轮仅新增公开规范检查脚本，不读取它们、不创建记忆引擎、不接入 HF。

## 五、隐私与来源边界

本地存储不等于不会进入远端模型、日志、备份或其他读取通道。key、summary、来源定位和事件流都可能敏感，按记忆内容同等处理；索引不含全文不能保证不泄露含义。

原设计只覆盖 default profile；家人或其他 agent 应使用独立 profile 与索引，不共享命中事件。Hermes H1 同样提醒避免两个进程共用一个 home。隔离是否真的生效需本机路径与权限测试，本次未验证。

第三方材料的事实摘录、用户偏好和可执行操作规则须区分来源与权限。保留来源标记、阻止摘要把网页指令升级成系统规则；这属于待实施的防错要求，不是已完成的安全评估。
